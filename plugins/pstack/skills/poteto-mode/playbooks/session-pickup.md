### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Locate the prior trail. A local transcript under Claude Code's per-project transcripts directory at `~/.claude/projects/<encoded-cwd>/*.jsonl` (where `<encoded-cwd>` is the workspace cwd with `/` → `-`. Do not glob across other directories under `~/.claude/projects/`, that crosses workspace boundaries and reads private chats from unrelated projects), a cloud-agent URL, or a pushed branch. Read the metadata overview and last messages first, then scan back for the decision points. When a handoff note exists, read it instead of the old thread. Read large files, logs and threads only as a targeted excerpt of about 4k characters per output, or have a Luna helper summarize them. Never re-read a skill or playbook already loaded; from another playbook read only the needed section with `rg` or `sed`. Cap read output at 2000 tokens (`max_output_tokens`); only build and test logs may exceed it, and then only their tail. One exec's whole output enters context, so never bundle several large reads into one exec; give them to a Luna explorer that returns only a summary. The 2000-token cap applies per call, not per file. Always read the spec, acceptance criteria, owner and verifier final states and the handoff note verbatim, in several 2000-token sections if needed, and never let Luna summarize them, because a summary can drop the detail a gate or acceptance hangs on. Parse a long transcript in a subagent and keep the reduced timeline in the main thread (the **principle-guard-the-context-window** skill). Pick each subagent's effort for the job, per the Subagents section.
2. Reconstruct operational state. The branch and worktree, what already landed (`git log`, `git diff` against the base), the open todos, the decisions made. The prior trail is authoritative input. Resist the bias to re-derive it.
3. Diff done vs pending. Compare what shipped against what was planned, name the resume point, do not re-run the prior repro or redo completed work. A "let me verify from scratch" pass means you're treating the trail as untrustworthy when it's authoritative.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest.
5. Verify the inherited claims against the original goal on the real artifact (the **principle-prove-it-works** skill). A passing prior self-report is not the proof.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome.
